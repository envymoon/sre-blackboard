01Why not just page the on-call?

A classic alerting stack tells you something is red. It doesn't gather evidence, rank hypotheses, or remember what worked last time. SRE Blackboard closes that loop.

CLASSIC ALERTING

Pages a human, then stops

Threshold fires → ticket created → on-call starts digging through dashboards from scratch. Every incident begins at zero.

SRE BLACKBOARD

Works the incident, then reports

The Harness fans out collectors, retrieves similar past cases, reranks hypotheses, and proposes a fix — the human only approves and audits.

BLACKBOARD PATTERN

Agents share one workspace

Coordinator, collectors, retriever, ranker, diagnoser and reporter never talk to each other directly — they read and write versioned artifacts on a shared blackboard.

05Safety is a gate, not a guideline

Every proposed action is classified R0–R4 before anything executes. The AI is read-only by default; the blast radius decides how much human is in the loop.

R0 · READ

Observe only

Queries, dashboards, log reads. Auto-approved, fully logged.

R1 · LOW RISK

Reversible tweaks

Cache purges, flag flips with instant rollback. Auto-approved.

R2 · CONTAINED

Scoped restarts

Single-pod restarts, traffic shifts <5%. Auto-approved with guardrails.

R3 · APPROVAL

Human required

Deploys, failovers, data migrations. Pipeline pauses until approved — try it in the demo.

R4 · FORBIDDEN ⛔

Never executed

Destructive or irreversible actions are rejected outright, no override.

07Run it yourself in 5 minutes

Local stubs stand in for MySQL / Redis / Elasticsearch until you provide real URLs — no infra required to start.

# 1. clone & install
git clone https://github.com/envymoon/sre-blackboard.git cd sre-blackboard
pip install -r requirements.txt

# 2. (optional) real infra — otherwise local stubs are used
export MYSQL_URL=mysql://root:pw@localhost:3306/sre REDIS_URL=redis://localhost:6379/0

# 3. replay the P0 baseline + run tests
python fixtures/make_p0.py
python -m pytest tests/ -q   # 37 passed
